# 📦 DVC Dataset Versioning Demo

This repository demonstrates how to use **DVC (Data Version Control)** to track dataset changes efficiently alongside Git.

The project shows how large files can be versioned without storing them directly inside Git while maintaining reproducibility of data versions.

---

# 🚀 Objective

The goal of this project is to:

* Understand how DVC tracks datasets
* Learn how `.dvc` files store metadata
* Separate data versioning from Git tracking
* Manage dataset changes using hash-based versioning
* Build a foundation for reproducible ML workflows

---

# 📂 Project Structure

```
DVC/
│
├── data/
│   └── data.txt          # Dataset tracked using DVC
│
├── data.txt.dvc          # Metadata file generated by DVC
├── .dvcignore            # Ignore rules for DVC
├── .gitignore            # Ignore rules for Git
└── README.md
```

---

# ⚙️ Steps Performed in This Project

## Step 1: Initialize DVC

```
dvc init
```

This creates the `.dvc/` directory to enable dataset tracking.

---

## Step 2: Add Dataset to DVC Tracking

```
dvc add data/data.txt
```

This command:

* tracks dataset using DVC
* creates `data.txt.dvc`
* prevents dataset from being tracked directly by Git
* stores dataset hash information

---

## Step 3: Dataset Version Update

After modifying the dataset:

```
dvc add data/data.txt
```

DVC updates the metadata hash automatically, enabling version tracking.

---

# 📊 What the `.dvc` File Stores

Example metadata tracked:

* file path
* file size
* MD5 hash value

This ensures reproducibility of dataset versions.

---

# 🔁 Why Use DVC Instead of Git for Data?

Git is not designed for large datasets.

DVC allows:

* dataset version tracking
* reproducible experiments
* efficient storage handling
* collaboration on ML workflows
